# Charlie 项目 - Agent 开发模式指南

## 概述

本项目采用 **oh-my-opencode** 多 agent 协作框架 + **Matt Pocock** 工程技能，构建高效、可靠的开发工作流。

### 核心原则

1. **Make impossible states impossible** - 类型安全，让错误状态无法存在
2. **Deep modules** - 小而深的接口，隐藏复杂实现
3. **Test at seams** - 只在 agreed seams 上测试
4. **Parallel execution** - 并行执行独立任务

## 开发模式

### 模式 1: ultrawork 全速开发

**适用场景**: 大型功能开发、复杂重构

```
ultrawork [任务描述]
```

**行为**:
- Sisyphus 作为主编排者
- Hephaestus 进行深度探索和执行
- Prometheus 负责规划
- Oracle 处理视觉/设计相关任务
- 自动并行化独立子任务
- 持续到任务完成

### 模式 2: hyperplan 对抗性规划

**适用场景**: 复杂架构决策、高风险重构

```
/hyperplan [任务描述]
```

**行为**:
- 5 个 hostile agents 从不同视角审查
- Pragmatist Skeptic 攻击过度工程
- Integration Tester 寻找遗漏的边界情况
- Autonomous Researcher 挑战无依据的主张
- Architect Strategist 发现结构性缺陷
- Creative Challenger 打破常规思维

### 模式 3: TDD + 多 agent 并行

**适用场景**: 新功能开发、核心逻辑实现

```
tdd [功能描述]
```

**流程**:
1. 使用 `domain-modeling` skill 明确领域术语
2. 使用 `codebase-design` 确定 seams
3. 在 seams 上写 failing test
4. Hephaestus 实现最小代码使 test 通过
5. Refactor（不在 loop 内）
6. 使用 `code-review` 审查

### 模式 4: work-with-pr 完整 PR 生命周期

**适用场景**: 需要创建 PR 的功能开发

```
implement and create PR for [任务描述]
```

**流程**:
- Phase 0: 拆分为原子 PR，创建 worktree
- Phase 1: ultrawork 驱动实现 + manual QA
- Phase 2: 推送并创建 PR
- Phase 3: CI + Cubic 验证循环
- Phase 4: 自动合并 + cleanup

### 模式 5: 安全审计

**适用场景**: 发布前安全检查、敏感代码审查

```
security-research [目标]
```

**行为**:
- 3 个 vulnerability hunters 并行扫描
- 2 个 PoC engineers 独立验证
- 按实际 exploitability 校准严重程度

## 项目特定说明

### Charlie 项目背景

- **类型**: Python 语音助手（FastAPI）
- **核心**: ESP32 + LLM + TTS 闭环
- **技术栈**: Python 3.12+, FastAPI, ESP-IDF

### 推荐的开发流程

1. **新功能**: `tdd` → `implement` → `code-review`
2. **Bug 修复**: `diagnosing-bugs` → `tdd` → `verify`
3. **架构变更**: `domain-modeling` → `hyperplan` → `implement`
4. **大规模重构**: `ultrawork` + `remove-deadcode`
5. **安全敏感代码**: `security-research`
