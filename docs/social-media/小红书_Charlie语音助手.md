# 我花3个月，在Mac上造了个中国版Jarvis 🤖

谁说Jarvis只有钢铁侠才有？
我自己做了一个，叫 **Charlie**，跑在我的Mac上，全家都能用。

---

## 它到底能干啥？

🎙️ **对话** — 按住说话，秒回，还支持打断（我说一半它停）
🌤️ **天气** — "北京今天穿什么" → 直接给穿搭建议
🎵 **音乐** — "放首歌" → 网易云自动播放
💡 **开空调** — "打开客厅空调，26度制冷" → 红外指令直接发
🧠 **记得住** — 对话历史、你的偏好、甚至记住了你爱喝什么
📅 **主动提醒** — 到点推送：该睡觉了/该吃饭了/出门带伞
📱 **连手表** — 接了个ESP32小手表，语音终端，走到哪问到哪

---

## 性能数据（技术党看这里）

| 指标 | 数字 |
|------|------|
| 语音端到端延迟 | **2.23秒**（说完话→听到回复） |
| ASR本地推理 | 26ms（SenseVoice，比百度快13倍） |
| TTS首句出音 | 69ms（百度TTS，比Finna快9倍） |
| MCP工具 | 19个，按需路由 |
| 测试 | 88个全绿，零失败 |

---

## 技术栈

- **前端**：纯HTML+JS，690行，无构建工具
- **后端**：Python FastAPI + Qwen-Agent
- **大脑**：火山引擎 ARK（deepseek-v4-flash）
- **语音识别**：SenseVoice 本地（237MB模型）+ 百度 + Vosk 离线三层降级
- **语音合成**：百度TTS（119ms）+ Finna 备用
- **IoT**：Tuya红外云API控制空调（踩了个坑，2C API不发码，改用2B开发者API）
- **硬件**：ESP32-S3 + xiaozhi协议，手表端Opus双向音频
- **部署**：Docker一键启动，Cloudflare隧道公网访问

---

## 踩过的坑

1. **涂鸦空调2C API是坑** — API返回success但红外码根本没发出去，查了两天才发现2C架构限制，必须走2B开发者红外云API。日志里"开机成功"全是误判。

2. **尾静音1.8秒是延迟大头** — 固定等30帧静音才断句，用户说完话还要等1.8秒。后来上了Silero VAD，神经语音检测，尾静音砍到0.48秒，感知延迟直接降28%。

3. **venv污染** — screen会话里VIRTUAL_ENV被hermes污染，python解析错了venv，warmup一直失败。改用绝对路径解决。
